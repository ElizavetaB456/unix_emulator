# Эмулятор командной строки UNIX-подобной ОС (вариант 3)

## Общее описание

Консольное (CLI) приложение, имитирующее работу в командной строке
UNIX-подобной ОС. Эмулятор разработан в пять этапов; каждый этап —
отдельный модуль `src/stageN.py`, класс `EmulatorN` наследует класс
предыдущего этапа и добавляет новые возможности:

| Этап | Модуль | Что добавлено |
|---|---|---|
| 1 | `src/stage1.py` | REPL, приглашение по данным ОС, раскрытие переменных окружения, заглушки `ls`, `cd`, команда `exit` |
| 2 | `src/stage2.py` | параметры командной строки, стартовый скрипт, команда `conf-dump` |
| 3 | `src/stage3.py` | виртуальная файловая система (VFS) из CSV, хранится в памяти |
| 4 | `src/stage4.py` | реальные `ls` и `cd`, команды `history`, `cal`, `who` |
| 5 | `src/stage5.py` | команды `mkdir`, `mv` (изменяют VFS только в памяти) |

Реализация — Python 3.8+, только стандартная библиотека.

## Функции и настройки

### Параметры командной строки (этапы 2–5)

| Параметр | Описание |
|---|---|
| `--vfs PATH` | путь к физическому расположению VFS (CSV-файл) |
| `--prompt TEXT` | пользовательское приглашение к вводу в REPL |
| `--script PATH` | путь к стартовому скрипту |

При запуске эмулятор выводит все параметры (отладочный вывод).
Стартовый скрипт выполняется до перехода в REPL: каждая команда
печатается вместе с приглашением, как если бы её ввёл пользователь.
Пустые строки и строки, начинающиеся с `#`, пропускаются. Выполнение
останавливается на первой ошибке, эмулятор завершается с кодом 1.

### Приглашение и парсер

* Приглашение строится по реальным данным ОС: `username@hostname:~$`;
  начиная с этапа 4 вместо `~` показывается текущий каталог VFS
  (`username@hostname:/home/user$`). Параметр `--prompt` заменяет его.
* Переменные окружения реальной ОС раскрываются (`$HOME`, `${HOME}`),
  аргументы в кавычках считаются одним словом. Незакрытая кавычка —
  ошибка `syntax error`.

### Команды

| Команда | Этап | Описание |
|---|---|---|
| `exit [код]` | 1 | завершить работу (код по умолчанию 0) |
| `ls [путь ...]` | 1 (заглушка), 4 | содержимое каталогов или имя файла; без аргументов — текущий каталог |
| `cd [каталог]` | 1 (заглушка), 4 | сменить текущий каталог; без аргумента — корень `/`; поддерживаются `.` и `..` |
| `conf-dump` | 2 | параметры эмулятора в формате `ключ=значение` |
| `history [n]` | 4 | история команд (все или последние n) |
| `cal [[месяц] год]` | 4 | календарь на текущий месяц, на указанный месяц или на год |
| `who` | 4 | пользователь, терминал и время входа |
| `mkdir [-p] каталог ...` | 5 | создать каталоги; `-p` — с промежуточными каталогами |
| `mv источник назначение` | 5 | переименовать или переместить файл/каталог (вместе с содержимым) |
| `mv источник ... каталог` | 5 | переместить несколько элементов в каталог |

Обрабатываемые ошибки: неизвестная команда, неверное число или формат
аргументов (`exit abc`, `cd a b`, `history x`, `cal 13 2026`), несуществующие
пути, файл вместо каталога, существующий каталог для `mkdir`, перемещение
каталога в самого себя, перезапись каталога файлом и наоборот.

### Формат VFS (CSV)

```
path,type,content,encoding
/,dir,,
/home,dir,,
/home/user,dir,,
/home/user/readme.txt,file,Hello from VFS,text
/home/user/logo.png,file,iVBORw0KGgo...,base64
```

* `path` — абсолютный путь. Вложенность задаётся путём: элемент
  `/home/user/readme.txt` находится в каталоге `/home/user`, который
  тоже должен быть описан в файле.
* `type` — `dir` или `file`.
* `content` — содержимое файла.
* `encoding` — `text` (по умолчанию) или `base64` для двоичных данных.

VFS загружается целиком в память; CSV-файл никогда не изменяется,
`mkdir` и `mv` работают только с представлением в памяти. Ошибки
формата (неизвестный тип, относительный путь, некорректный base64,
отсутствующий родительский каталог, повтор пути) сообщаются с номером
строки, эмулятор завершается с кодом 1.

## Сборка и запуск тестов

Сборка не требуется. Для тестов нужен pytest:

```sh
python3 -m pip install -r requirements.txt
python3 -m pytest -v          # или: make test
```

Запуск эмулятора:

```sh
./run.sh --vfs examples/vfs_deep.csv                  # этап 5
STAGE=1 ./run.sh                                      # этап 1
make run STAGE=4 VFS=examples/vfs_deep.csv PROMPT="emu> "
python3 -m src.stage2 --help
```

В Windows: `run.bat` (этап задаётся переменной `STAGE`, например
`set STAGE=4`).

### Демонстрационные скрипты

| Скрипт | Что проверяет |
|---|---|
| `scripts/test_stage1.sh` | REPL, переменные окружения, заглушки, ошибки, `exit` |
| `scripts/test_config.sh`, `.bat` | все параметры командной строки (этап 2) |
| `scripts/test_vfs.sh`, `.bat` | минимальная VFS, несколько файлов, 3+ уровня вложенности, ошибки загрузки |
| `scripts/test_stage4.sh` | все режимы `ls`, `cd`, `history`, `cal`, `who` и их ошибки |
| `scripts/test_stage5.sh` | `mkdir`, `mv` и их ошибки, неизменность CSV |
| `scripts/test_stages.sh` | все перечисленные скрипты подряд (`make demo`) |

Стартовые скрипты эмулятора: `examples/startup_stage2.txt` …
`examples/startup_stage5.txt`; каждый заканчивается намеренной ошибкой,
чтобы показать остановку скрипта. Примеры VFS: `examples/vfs_minimal.csv`,
`vfs_many.csv` (с двоичным файлом в base64), `vfs_deep.csv`
(4 уровня вложенности), `vfs_invalid.csv` (ошибка структуры).

## Структура репозитория

```
src/          исходный код этапов 1-5
tests/        тесты pytest (общие фикстуры - tests/conftest.py)
examples/     примеры VFS и стартовые скрипты эмулятора
scripts/      скрипты ОС для демонстрации этапов
run.sh, run.bat, Makefile   запуск эмулятора, тестов и демонстраций
```
